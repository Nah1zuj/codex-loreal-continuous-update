## 结论

在固定 Git `main` `db485ed098d433758358e8cc6280af5d4003afe1` 的独立本地实例上，Mac Chrome 的 100%／200% 页面缩放、跳到正文、连续键盘焦点、应用内“放大正文”键盘开关，以及文字输入、语言切换、朗读暂停／继续和隔离日志保存流程通过。本轮没有启动 VoiceOver，没有取得实际播报文本，也没有访问麦克风或摄像头；因此只补充键盘与缩放软件／实体浏览器证据，不改变 Issue #3 的双平台读屏待验收状态。

## 完整键盘文字流程补充

第二个独立实例仍使用相同业务代码基线，页面／后端／语音端口为 `61990`／`61991`／`61992`，数据目录为 `work/issue3-keyboard-flow`。分支上的证据文档提交不改变被测业务代码。启动复用与锁文件完全一致的本机既有 Python／前端依赖，不属于净安装。

| 场景 | 实际键盘操作与观察 | 结果 |
| --- | --- | --- |
| 进入文字模式 | 从首页跳到正文，按 `Tab` 到“开始体验”，按 `Return` 进入倾听，再用 `Tab`／`Return` 切到“文字” | PASS |
| 输入与提交 | 在文字框逐键输入合成英文需求 `Tomorrow I will meet friends and want a natural relaxed formal look.`，按 `Tab` 到“发送”并按 `Return` | PASS；收到 mock 文字回复 |
| 语言切换 | 键盘将“中英双语”切到“英语优先”，页面控件名称随之显示英文，再恢复“中英双语” | PASS；焦点保留在语言选择器 |

首次启动命令在仓库根目录执行时被隔离路径保护直接拒绝，没有启动服务或写入数据；改从应用目录执行后正常启动。这是操作目录错误，不记作产品失败。中文合成句通过原生按键自动化只能输入标点且没有提交，随后改用英文合成句完成逐键输入；本轮不能据此判定中文输入法兼容性。

## 边界与剩余事项

- 辅助功能树提供控件名称、角色、值和焦点证据，但不是 VoiceOver 实际播报。
- 本轮已完成文字提交、语言切换、页面主动朗读暂停／继续、停止会话、草稿未授权保护和明确保存；没有单独的“拒绝草稿”按钮，因此只证明未同意时不会保存，不能扩大成显式拒绝操作已验收。
- Mac 仍需在实际 VoiceOver 下记录播报内容、顺序、打断和重复情况；启动或修改系统辅助功能设置应由用户明确同意。
- Windows 仍需在 Issue #2 环境可用后完成 Chrome＋NVDA 同版本场景。
- 真实麦克风、扬声器、耳机和相机分别属于 Issue #4、#5，不由本记录判定。
