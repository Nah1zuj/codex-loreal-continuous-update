# TRACE 工程章程

## I. 会话只有一个业务权威

服务端负责会话和教学计划的状态变更。旧接口只能转换参数与结果。显式命令用同一事件标识重试，校验当前版本或预期步骤，迟到结果不覆盖较新的快照。闲聊、否定、询问、重复和解释不推进课程。

## II. 权限与保存由用户分别控制

暂停保留教学进度。恢复不得恢复媒体授权。预览、本地单帧、持续观察、对比和远程图片上传各有独立生命周期。摘要、日志、偏好按候选和版本分别确认。迁移保留旧记录来源，删除必须覆盖派生内容和未来上下文，数据按用户隔离。

## III. 证据与能力边界

课程、产品、模型和观察结果提供可追溯来源，明确事实、建议和不确定性。视觉仅覆盖质量、定位和条件允许时的颜色比较。模拟、研究与真实服务分别标注。工程候选版与真实试用版分别验收。

## IV. 无障碍是核心行为

文字、键盘和读屏可以完成核心任务。语音保留按钮和起止词，单段限制为 120 秒。媒体故障、拒绝授权和网络失败都要保留可用的文字路径。

## V. 先规格再实施，兼容需要退出条件

按阶段执行 constitution → specify → clarify → plan → checklist → tasks → analyze → implement → converge。每项行为变更关联需求、任务、测试和证据。先保护正确行为，再迁移真实调用方，验证后退出旧实现。按业务主题拆分提交。数据迁移与回退都有可复查证据。

## VI. 验收与实际运行绑定

测试隔离数据库、端口与配置。按 PASS、FAIL、NOT RUN、BLOCKED 记录软件测试、真实服务、实体设备和人工验收，绑定代码、运行环境、模型和知识库。实际评审者确认自定义清单。无未解决 P0 和核心 P1 且 Mac、Windows 实测完成方可交付工程候选版。真实试用还需专业课程审核及盲人或低视力参与者验证。

## 治理

变更章程须说明受影响的规格、迁移和验证责任。阶段实施者可评估规格质量，独立评审与实体证据由实际参与者提供。
