# 会话控制实施方案

## 设计与顺序

1. 在完成操作与旧回忆路由移除自动写入。保留旧表及删除入口；返回仅供本次展示的小结。清理模型和界面自动保存措辞。
2. 复核教练、旧 routine、流式工具与 Reflect 的入口。以服务端命令服务统一操作；旧请求映射为同一命令。课程内容、领域与来源不复制。
3. 扩展 SQLite 事件记录，持久关联命令参数及提交结果。只有成功事务产生可查询的事件。历史事件可继续防重。旧计划数据按读取兼容。
4. 前端统一请求生命周期与会话快照。断连时先查原事件和权威状态。语音/相机资源继续由原控制器释放，授权状态与业务进度分离。

## 迁移及回退

第一批修改不迁移 SQLite。旧回忆仍可查看、清除；运行验证使用独立数据库。事件迁移及其回退在改表前定稿，并用旧 SQLite 结构进行测试。阶段 0 基线已保留，代码按业务主题提交。不要用旧版自动保存行为处理当前用户会话。
