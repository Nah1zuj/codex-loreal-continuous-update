# 双平台实机验收

本页记录设备操作及复测方式。自动化结果见 [阶段 8 验证](verification.md)。一个场景可以只通过其中的键盘操作，读屏发声和硬件效果分别填写。

## macOS 本轮观察

2026-11-07，macOS 26.3（25D125，Apple Silicon），Chrome 156.0.8078.81，VoiceOver 10。通过独立本机服务和无痕窗口测试，输入为虚构场景。浏览器工具栏实际显示 200%。测试后恢复到 100%、关闭无痕窗口和旁白，停止测试服务。

| 场景 | 操作与观察 | 结果 |
|---|---|---|
| 键盘进入正文 | 首次 Tab 到「跳到主要内容」，回车后地址出现 `#main-content`，焦点移到正文。接着按 Tab 可到语音、视觉和文字入口。 | 键盘通过 |
| 麦克风拒绝 | 用 Tab 到「开启语音引导」，在 Chrome 原生权限框用 Tab 到「一律不允许」，按空格拒绝。页面提示可通过文字继续。原版同时残留等待权限提示，修复后在同一拒绝权限下重试，提示消失。 | 拒绝、文字退路及过期提示修复通过 |
| 摄像头拒绝 | 用 Tab 到「开启摄像头」，Chrome 原生权限框列出内建相机。用 Tab 和空格拒绝，页面显示「摄像头权限被拒绝」，图片入口和文字操作仍在。 | 键盘通过 |
| 拒绝后继续文字和处理小结 | 返回文字页，用 Tab 到输入框，逐键输入虚构内容，经「发送」确认收到回复。用 Tab 和回车将「准备与补水」推进至「轻薄底妆」，提前结束并查看小结。审阅框默认未勾选且保存禁用，选择「不保存这份摘要」后显示「暂无已存摘要」。 | 键盘通过 |
| 语言与字号 | 用键盘从中英双语切到「英语优先」，焦点仍在语言选择器。Chrome 的辅助功能树显示英文输入框名称。用 Tab 和空格开启放大正文，200% 下输入框仍在。 | 本轮场景通过 |
| 读屏播报和打断 | 上述拒绝及文字操作时系统 VoiceOver 已运行。可读取 Chrome 的焦点、控件名称和页面状态。实用工具显示字幕面板已开启，但本次未取得字幕或听到播报，无法核对播报内容、顺序和重复情况。 | 待人工复核 |
| 实体音视频 | 原生权限框列出了 Mac 内建麦克风和相机。测试只走拒绝路径。 | 实际录音、回放、耳机、相机采样待实测 |

第二次使用系统旁白的复制最近播报短语命令尝试取证，未获得可核对的播报文本。已恢复旁白设置并关闭本次隔离窗口和服务。Mac 的实际播报仍需现场听记或字幕摘录。

## 两端复测步骤

1. 按 [运行说明](../../AccessibleBeautyAgent/README.md) 在独立测试目录安装和启动。记录压缩包内清单中的提交、系统、Chrome、读屏器和设备版本。首次复测保持 mock；后续供应商联调使用单独配置和合成测试资料。
2. 开启系统读屏器。Mac 使用 VoiceOver 字幕面板或现场听记，Windows 使用 NVDA 语音查看器或现场听记。Chrome 先用 100% 检查，再将实际缩放调到 200%。用 Tab、Shift+Tab、回车和空格完成操作，记录每次错误后的焦点位置。
3. 从页面顶端跳到正文。在文字页输入虚构需求，明确开始，推进一步，暂停后恢复。切换语言、放大正文并检查减少动态效果。核对页面可操作、焦点可见、读屏能找到文本框并获知课程状态。
4. 分别触发并拒绝麦克风和摄像头的首次授权。核对提示可理解、等待状态已结束，且无需刷新即可继续文字。结束课程，打开小结，选择放弃，再复查记录为空。另开一轮，审阅并确认保存，核对只出现一条记录。
5. 由现场人员在同意后，分别检查真实麦克风、扬声器和耳机。录入测试短句，检查录音、转写、回复、打断、撤权、重试，以及切页和刷新后的资源释放。保留播报摘录，检查默认应用静默、主动朗读、读屏顺序及是否重复播报。相机使用经同意的测试素材，检查预览、明确同意后的单帧、本地失败提示和停止后的资源释放。
6. 真实文字供应商与标签识别另行联调，记录服务配置类型、是否实际调用及输出边界。课程审核和目标用户试用分别记录评审条件、结果和未关闭项。

| 平台与版本 | 场景及输入 | 期望结果 | 实际结果及状态 | 时间、评审人及证据 |
|---|---|---|---|---|
| Windows Chrome＋NVDA | 步骤 1 至 5 | 可用键盘和读屏完成，权限拒绝和中断后可恢复 | 待 Windows x64 实机 | 待填写 |
| Mac Chrome＋VoiceOver | 步骤 3 至 5 的实际播报与实体媒体 | 可听到准确提示并控制打断，可结束录音与拍摄 | 待人工复核及真实设备操作 | 待填写 |
