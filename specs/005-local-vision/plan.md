# 本地视觉实施方案

## 设计

1. 前端预览继续由现有相机资源控制。手动、连续及单次照片授权在现有组件的明确动作后向同一个视觉 API 取得范围凭据，再进行截帧或送图。撤销仅使对应范围失效；全停清除所有本地范围。切换摄像头先释放原分析范围。
2. 服务端视觉路由使用同一会话锁校验身份、凭据和过期。记录会话对象及媒体版本，推理在锁外运行，提交前再次检查。会话撤销入口主动清除视觉内存。定时清理用于过期与会话淘汰。
3. 只保留最近一帧证据和经授权的数值基线；移除隐式历史比较和本地检查后的远程模型补充。模型缺失时以 OpenCV 质量门和区域代理降级，降级不跨帧比较。照片仅用图像坐标。
4. 对照合成输入、后端隔离数据库、真实浏览器前端和设备验收分层记录。联调使用同版本前后端；前端未升级的旧单帧请求应拒绝，避免绕过凭据。

## 迁移与回退

无 SQLite 变更。按同一版本回退前端和 API，重启清空所有临时授权与基线；旧版无范围凭据和显式基线规则，不能作为本规格的发布版本。旧人脸接口拒绝非 mock 配置下的图像分析。它只为已有本机模拟兼容路径保留；真实人脸使用本地检查。
