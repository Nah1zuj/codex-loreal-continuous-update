A. 全程语音目标与首次配置边界

盲人主流程的验收目标是全程语音，不是“读一下欢迎语，随后要求用户找按钮”。完成必要的首次环境配置后，进入首页、开始体验、回答需求、进入映照、操作妆教、暂停、唤醒、结束本次装扮都不能要求用户看屏幕或触摸网页按钮。
每个阶段要读出当前所在步骤、下一步可以说什么和操作结果。需要输入时明确问一个问题，等待回答；没有回答时不能替用户做决定。
首次浏览器/操作系统麦克风许可属于独立的环境配置，不是拾光业务流程，也不能被代码取消。提供Apple旁白/语音控制的首次配置说明及系统辅助操作路径；Mac演示可提前完成必要配置。
分别记录“首次环境配置是否可无手完成”和“配置后的产品主流程是否全程语音”。如果目标设备的首次弹窗只能触摸操作，明确记录此限制；不能把“请别人点一下”或手动按钮备用写成首次全语音已经通过。
必须区分网站的体验选择、浏览器的麦克风许可、操作系统的麦克风许可。
网页不能在未获得麦克风许可时听见“同意”，也不能自动批准浏览器/系统弹窗。禁止模拟许可通过、自动点击“允许”、用脚本绕过权限、反复弹窗催促或隐藏麦克风使用状态。
Apple系统语音控制可通过控件名称操作界面；屏幕编号可以辅助操作，但不能把“看编号、再说编号”作为盲人的唯一入口。具体浏览器/系统的权限对话框必须实机核查；系统语音控制和网页语音引擎是独立系统。
保留原生、可聚焦且名称清楚的“开启语音引导”配置/恢复控件，供手动操作或系统辅助操作启动；不能让它成为已配置盲人主流程中的强制点击步骤，也不能重新包装成被删除的“开始今天的造型”业务按钮。
自动欢迎播报、语音采集启动和浏览器用户激活限制必须一起实测。首次加载无法发声时，借助系统读屏与可访问的启动控件完成首次激活；不能承诺所有浏览器加载即发声。已配置环境每次进入仍需手点才能继续时，R3未通过。
麦克风已授权并实际开始采集后，“同意”可回答网站当下提出的选择问题，不代表新的系统授权。有效许可应复用，不能每个页面或每次唤醒都重新弹授权。
拒绝、设备不存在、权限撤回和能力不支持时，给出系统读屏可识别的恢复说明与手动备用入口；备用入口的存在不等于全语音验收通过。
摄像头许可在需要映照预览/检查时单独申请，麦克风同意不得代替摄像头同意。

B. 状态与不变量

分别维护：麦克风状态、交互方式、播报开关、语音控制状态、页面/引导阶段和请求世代。不要用单一 paused 布尔值代表全部含义。

至少包含以下语音控制状态（名称可适配代码，语义不可改变）：
UNAUTHORIZED：麦克风尚不可用；不能声称正在聆听。
ACTIVE：允许普通对话和语音导航；按用户选择输出语音/文字。
QUIET_WAKE：暂停回应，仅在本机侦听约定的唤醒词。
STOPPED：用户通过“关闭麦克风”按钮完全停止聆听，释放本应用持有的媒体轨道、识别器、音频节点与连接。
ERROR：能力不可用，显示恢复路径，不无限重启或继续请求权限。

QUIET_WAKE 的“后台”指应用处于静默待命，不保证浏览器标签切到后台、锁屏、睡眠或关闭页面后继续工作。这些场景分别测试、标明支持情况。
QUIET_WAKE 中：不生成回复、不播报普通聊天、不将普通话语加入会话或记忆，不向远程识别服务/大模型发送环境音或转录。只允许本机唤醒检测所需的短暂处理和有界内存缓冲，及时丢弃，不保存录音。
浏览器原生 SpeechRecognition 可能使用云端识别；即使屏幕没有显示文字，也不能把持续运行它称为“本地静默”。确认设备端能力与中文可用性后才能使用；否则采用明确的本机方案，不偷偷降级为云端常听。
页面须明确显示“暂停回应，仍在侦听唤醒词”，保留可访问的“关闭麦克风”按钮。进入QUIET_WAKE立即停止产品输出；不再播报暂停确认或反复朗读唤醒词。静默期间也不通过自动aria-live反复读出普通状态；用户主动调用系统读屏时仍能查看状态。

C. 命令优先级与行为

按钮事件优先：点击“关闭麦克风”立即结束采集与输出，清空临时音频，转入STOPPED。此按钮在聆听、思考、播报、静默等待等状态中都可操作，不受模型请求busy锁死。恢复需启动控件或系统辅助操作；关闭后网页麦克风不能自行听见唤醒词。
不注册“关闭麦克风”“完全停止聆听”“退出语音”等专门关闭麦克风口令；不要在欢迎词或帮助词中教用户用语音关闭麦克风。普通聊天出现这些词也不得触发设备关闭。
用户主动关闭麦克风只由按钮触发。系统权限撤回、页面卸载、设备断开等仍按正常生命周期清理资源；这些不是产品语音命令。

语音命令优先级：
P1 软暂停：“请终止对话”“暂停语音”“暂停回应”。取消在途回复与播报队列，转入QUIET_WAKE，保留麦克风的唤醒侦听和当前业务进度。它不结束业务会话，不释放麦克风。
P2 唤醒：“重新启动语音交流功能”为主词；“重新开启语音功能”为别名。有效唤醒后转入ACTIVE并恢复输出，保留会话与页面。它不是重启服务，不新建或清空业务会话。
P3 页面导航与完成指令。
P4 普通业务对话。
QUIET_WAKE只处理唤醒；普通业务对话和导航词在唤醒前均不执行。

控制命令由确定性的本地路由处理，不交给大模型决定系统许可或麦克风开关。避免泛化匹配“停止”导致意外退出。若保留旧版本“停止/stop”口令，将其统一到软暂停，不得继续直接调用结束监听的方法；暂停与核心流程完成均不能转入STOPPED。
说“停止语音播报”或点击“关闭语音播报”：立即取消当前及排队TTS，进入安静状态；已授权的唤醒侦听保留。按钮操作可以切到手动探索；语音停止后用户仍可通过约定唤醒词恢复全程语音。不要根据这些操作推断用户视力或自动关闭麦克风，不增加单独的“授权保持聆听”对话。
语音软暂停和按钮关闭麦克风在模型回复、流式播报、页面切换、等待响应时都须有效，不能只在系统说完后才生效。软暂停需要真实的语音打断监听/回声控制，不能仅靠一个按钮声称已支持。
暂停后迟到的模型响应、旧识别回调和旧 TTS 回调不得重新输出或恢复聆听。使用现有取消与请求世代机制，覆盖新状态的竞态。

D. 同一句话中的唤醒与后续指令

用户说“重新启动语音交流功能，进入映照”：只把“进入映照”作为新的导航命令执行一次，不丢失、不重复，不将唤醒前闲聊带入对话。
用户说“重新开启语音功能，今天想要淡一点的妆”：只把后半句作为本次新输入处理一次。
只说唤醒词：恢复后简短回应“我在，请继续”，等待下一句。
软暂停词后附带的普通内容不继续执行。带否定、引用或讨论语境的词句（如“不要重新开启语音功能”）不应仅因包含关键词而激活；设候选校验和误触发测试，并记录实际结果。
必须设计唤醒词边界、检测延迟、短时缓冲与后半句识别。不能假设重新调用现有 SpeechRecognition.start() 能找回启动前已经说出的音频。若采用本地关键词检测，需要另一个可处理唤醒后音频的识别路径；关键词模型本身不会转录后半句。
缓冲有严格时长和内存上限；仅用唤醒后当前话语所需片段，唤醒前内容丢弃。不要上传整段静默历史。TTS回声不能使应用自我暂停或自我唤醒。
长唤醒词的识别率、响应时延和同句边界均需实测；不承诺百分之百准确。

E. 推荐验证路线

先检查现有 Web Speech 生命周期和设备端中文能力，随后优先验证 sherpa-onnx 中文自定义关键词检测与本地识别接入，保持现有 FastAPI 和模型对话 API。
可验证的结构：浏览器在正式授权后采集音频 → 本机 127.0.0.1 语音处理端（或已证实可运行的设备端模块） → 静默只检测控制词 → 唤醒后识别有效指令 → 现有业务 API。
本机服务不等于远程部署服务。将来远程托管时，必须重新说明音频去向，不能继续声称“完全在用户本机”。
核查代码与模型各自许可证、模型文件来源/校验值、Mac/Windows/当前 Python 版本兼容性与启动生命周期。不要让云端大模型负责常听，也不要为了新库破坏现有可运行环境。
无法达到本地静默或同句续接时，将该条标为未完成，并给出原因；不能用视觉动画或预设回复伪装成功。

当前源码线索：
frontend/src/realtime/callController.ts：pause() 会调用 cancel()，结束识别；
frontend/src/realtime/voice.ts：当前 startCycle 使用非连续浏览器识别；
frontend/src/App.tsx：路由、播报、手动输入和会话协调；现有记忆同意逻辑需要与R5新目标区分，不能直接沿用成每次回忆前的授权流程。
继承其竞态处理，不把功能做成互不知情的第二套监听器。

六、R4：首页—倾听—映照动线

首页：删除“开始今天的造型 → / Begin today’s styling →”按钮。保留导航、故事入口以及必要的语音/手动入口，使移除按钮后仍可理解如何继续。
具备播报条件时，首次介绍一次即可；不要因重渲染、导航回首页、流式响应而重复欢迎语。
首次已配置体验的介绍草稿：“欢迎来到TRACE。我会用声音陪你完成今天的装扮。说‘可以开始’，我们进入倾听；需要安静时，说‘请终止对话’；想继续时，说‘重新启动语音交流功能’。你随时可以让我重复说明。”
后续回访欢迎语优先结合R5中的真实上次妆容，保持简短，不每次重复整段教程。用户说“帮助/我可以说什么”时再解释当前可用命令。
播报前核查当前状态，只讲当下能用的操作；未授权时提供首次配置指引，不能让人以为正在听。关闭麦克风按钮不作为盲人主流程中的必做步骤。

首页 ACTIVE 状态听到“可以开始/开始体验”：进入2倾听，并简短说明可描述场合、妆容偏好和需求。进入页面本身不应偷偷新开多次会话。
倾听：问题、回答、修改偏好和进入下一页均支持语音，不要求填写表单或点击完成。文字与控件供其他操作方式使用。“完成/倾听完成/进入映照”在此页面触发进入3映照。播报“现在是第三步，映照”及当前可说指令，保持已有偏好和建议。
映照：以可听的妆教为主，支持语音重复、解释、下一步、上一步、跳过、检查和完成。若需要摄像头姿势调整，用声音指导并说明真实检查是否成功；不能只显示框、箭头或颜色让用户自己看。
“这一步完成/下一步”用于妆教步骤；明确的“结束本次装扮”用于结束核心体验。倾听中的“完成”进入映照；映照中的“完成”按当前步骤上下文处理，需结束整个体验时明确提示“结束本次装扮”。不能让同一识别结果既推进步骤又结束会话。
若原有阶段中“完成”存在冲突，按当前引导上下文明确提示可说的命令，并使用“结束本次装扮”消歧；不能为了路由把未完成步骤、未确认方案或数据库记录直接标为成功。
核心体验结束后给出简短回顾，停留在可操作的完成状态；不强制跳到拾光。按R5形成下次可用的真实妆容摘要，不弹授权步骤。结束装扮与暂停回应、关闭麦克风是不同事件：说“结束本次装扮/完成”不能自动关闭麦克风或使用户无法继续语音。继续允许语音导航、帮助、软暂停和唤醒。
语音陪伴模式支持“再说一次/帮助/下一步/上一步/跳过”及必要的业务选择，错误也要用可听说明表达。无回答、识别不确定时不得静默推进；保留当前步骤并给出简短重试提示，软暂停中保持安静。
所有路由变化同步可见标题、当前导航和键盘/读屏焦点；避免自带TTS与aria-live同时重复长段播报。

体验命名采用用户提出的“全明/黑暗”作为体验偏好名称，可显示“全明 · 手动探索 / 黑暗 · 语音陪伴”，配一句“按偏好选择，随时切换”。不采集或推断视力身份，不因关闭播报就给用户贴标签，也不据此屏蔽页面。此命名不要求新增黑色主题。
“关闭语音播报”进入手动探索；未关闭且已选择语音并获许可时，继续语音陪伴。权限不足时不能将“没有点关闭”当作许可。

七、R5：拾光自然接续上次体验

产品意图：下一次使用时，TRACE自然记得与这位用户上次一起做过的妆容，让人感到熟悉、被记住。拾光是主流程背后的延续能力；用户不必进入拾光页面、点击读取记忆或逐次批准，主流程也不添加记忆授权环节。
本轮产品默认启用必要的妆容摘要与回访提及。不要新增“是否授权保存记忆”“是否授权读取拾光”“同意后才能继续”的弹窗或口头确认，不把是否同意保存/读取作为欢迎语或下一步的前置条件。
可在设置/拾光中提供简短的记忆用途说明、查看和清除能力，供用户主动使用；不要把说明、开关或清除设置做成每次必经步骤。用户主动关闭或清除后应尊重该设置。

记录范围与事实依据：
1. 主流程正常完成后，保存本次妆容的必要结构化摘要，例如妆容名称、场合、已完成步骤、用户自己表达的喜好或修改意见。按会话/记录ID幂等更新，避免重复。
2. 普通流程中的反馈可以形成下次可用的摘要；静默期间的话语、原始录音、照片和整段聊天不属于本轮自动保存范围。未完成只记真实进度，不能记成成功完成。
3. 摘要绑定实际的同一用户或本地演示身份，跨会话/页面刷新/应用重启可读取；不能只存在React组件内存中，也不能把上一位用户的数据带给下一位用户。
4. 复核现有记忆、妆容与私人日志接口。R5的妆容摘要与回访提及不应被旧memory_consent步骤绑成授权产品；如接口需要适配，仅调整完成R5所需部分。不要将其他私人日志的全部内容自动纳入此次摘要，也不要伪造现有确认状态来绕过接口。

下次自然提及：
进入下一次首页语音介绍或倾听时，在已有可用记录且正常交流开启的情况下，主动提起最近一次相关妆容；每次新体验最多主动提起一次，进入映照时衔接同一上下文，不再次重复欢迎或读出整份档案。
实例：“又见面啦。上次我们一起尝试了柔和的日常妆，今天想延续这个感觉，还是换个风格？”
如果用户确实说过喜欢，可说：“上次那款淡妆，你说很喜欢。今天我们继续那个感觉，还是试一点新的？”
“沿用还是换风格”是本次妆容选择，不是对读取/保存记忆的授权。等用户作出本次选择，不自动替用户决定沿用。
如果只有讨论/推荐记录，就说“上次我们聊到……”，不要说已经画完；没有真实视觉评价或用户反馈时，不凭空宣称“上次你的妆画得很好看”。用熟悉的细节和温和语气传达亲切感。
用户说“换一个/重新开始/不要提上次”时，直接转向本次需求，不继续劝说沿用。无记录、记录已清除、无法读取时正常开始，不虚构往事，不阻塞主流程。
需要长期关闭回忆或清除记录时，提供语音可达的拾光/设置操作；不要求盲人只能看屏幕操作。
妆容记录是产品记忆，本轮不开展模型训练。

八、实施顺序、验收与交付

只有进入 IMPLEMENT 后执行以下阶段。每阶段先确认输入，再实施最小必要改动，完成有意义的验证；同一授权范围内不额外设置逐步审批。

P0：核对正确目录、现有改动、素材与能力。记录源码/资源回退方式；不要覆盖既有未提交工作，不复制或输出 .env、密钥、录音或私人日志。
P1：统一装饰人物、调整编号和字号、移除首页业务按钮，核查所有页面及静态/减少动态回退。
P2：验证中文本地唤醒与同句续接的技术路径，处理首次配置、播报、语音软暂停、仅按钮关闭麦克风和竞态。
P3：接通三步全语音路由、步骤/页面完成消歧、妆容摘要与下次自然回访，不新增记忆授权环节。
P4：运行现有相关测试、实机语音与视觉验收，记录结果。未来若更新交付包，同步双端说明、资源来源与完整性清单，不打包 .env、虚拟环境、node_modules、私有数据库或录音。

必须可观察的验收场景：
AC01 六个主页面及其回退：没有旧装饰人物残留；苹果、文字保持正确；摄像头真实画面未被替换。
AC02 在桌面和窄屏及200%缩放下，六项编号可见、可操作、顺序正确；键盘焦点和读屏名称明确。截图需包含实际视口尺寸。
AC03 首页不存在旧“开始今天的造型”按钮；具备清楚的手动导航和语音启动入口。
AC04 首次未授权：不会谎称正在听，不会自动批准许可；分别记录允许、拒绝、撤回、不支持和自动播报受阻的实际表现。
AC05 首次配置与主流程分别验收：核查系统读屏/语音控制能否完成启动和权限弹窗，记录系统、浏览器版本及是否需要触摸。不把看编号或请人点击当作盲人全语音路径。未测试不能写“支持”。
AC06 已配置环境中，从首页欢迎到倾听、映照、结束装扮全程不看屏幕、不点击网页按钮：语音可以开始、回答/修改偏好、完成倾听、重复/帮助/下一步/跳过/检查及结束装扮均有效，页面变化和结果可听懂。不强制进入拾光，结束装扮后仍可语音操作。
AC07 回复和TTS进行中说“请终止对话”：旧输出停止，QUIET_WAKE仍可唤醒。静默普通闲聊不触发模型请求、路由、日志/记忆写入或语音回复；用请求计数和本机服务记录证明，不只看屏幕。
AC08 两个唤醒词、单独唤醒、唤醒词紧接导航、唤醒词紧接业务话语：后半句各执行一次，唤醒前普通内容不进入会话。
AC09 否定/引用、背景噪声、TTS回声及连续暂停—唤醒：记录误唤醒与漏唤醒，不使用未实测的准确率。关键控制先做确定性测试，再做真实麦克风试验。
AC10 点击“关闭麦克风”按钮：所有本应用音轨/识别与音频连接释放，不自动重开；按钮在busy和QUIET_WAKE时仍有效。说出“关闭麦克风/完全停止聆听/退出语音”不触发关闭；旧“停止/stop”若保留则执行软暂停。麦克风关闭后网页不能假装听到唤醒；其他应用占用设备不由本应用控制。
AC11 语音停止播报或按钮关闭播报：TTS队列清空，麦克风没有自动关闭；已配置环境中可通过约定唤醒词恢复全程语音，手动探索也可用，不增加保持聆听的授权对话。
AC12 导航、暂停、结束期间旧模型/识别/TTS回调不会继续说话或重开麦克风；同一句指令不重复发送。
AC13 完成妆容后刷新/重启并开启下一次同用户体验：能自然提起真实的上次妆容且只提一次，全程没有保存/读取记忆授权步骤。选择换风格后直接继续新需求；无记录、未完成、清除、关闭回忆、读取失败和切换用户均表现正确。不保存或重放静默内容。
AC14 标签切后台、锁屏、断网、设备拔出、权限撤回：说明实际行为与恢复方式，不保证网页具有系统级常驻能力。
AC15 Mac和Windows启动仍可用；未经Windows实机验证就标为未测试，不能把Mac结果当双端验收。

验证计划（不是本轮已运行的结果）：
前端：在 frontend 中执行 npm test 与 npm run build；对关键语音状态/竞态、指令分流、仅按钮关闭麦克风、跨会话回忆与重复提及防护增加必要测试，UI小改动以实际浏览器检查为主。重点是应用真实语音路径，不用测试脚本直接调用事件替代全语音验收。

本轮不安装库、运行新模型、触发麦克风/摄像头许可或改动测试；这些属于后续实施。
