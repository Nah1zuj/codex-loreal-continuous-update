五、R3：授权、播报、暂停与唤醒

A. 首次进入与授权边界

目标是在支持的设备上尽量无手操作。必须区分：网站的体验选择、浏览器的麦克风许可、操作系统的麦克风许可。
网页不能在未获得麦克风许可时听见“同意”，也不能自动批准浏览器/系统弹窗。禁止模拟许可通过、自动点击“允许”、用脚本绕过权限、反复弹窗催促或隐藏麦克风使用状态。
Apple 系统语音控制可作为首次操作的辅助路径：用户预先启用系统功能，通过控件名称或系统编号操作网页；是否能完成具体浏览器/系统的权限对话框，必须实机核查，不预先保证。系统语音控制和网页语音引擎是两个独立系统。
提供原生、可聚焦且名称清楚的“开启语音引导”控件及授权说明；在浏览器要求用户激活时，通过该控件启动。这个权限入口不能重新包装成被删除的“开始今天的造型”业务按钮。
自动播报首页欢迎语须进行目标浏览器测试。若首次加载未允许播报，则使用读屏友好的介绍和明确的启动控件，由系统语音控制/键盘/协助完成首次激活。不能承诺每个浏览器一加载就发声。
麦克风已授权并实际开始采集后，“同意”可以确认网站内的体验选择；它不代表新的系统授权。拒绝、设备不存在、权限被撤回和不支持语音时，提供可读的文字说明及手动入口。
摄像头许可在需要映照预览/检查时单独申请，麦克风同意不得代替摄像头同意。

B. 状态与不变量

分别维护：麦克风状态、交互方式、播报开关、语音控制状态、页面/引导阶段和请求世代。不要用单一 paused 布尔值代表全部含义。

至少包含以下语音控制状态（名称可适配代码，语义不可改变）：
UNAUTHORIZED：麦克风尚不可用；不能声称正在聆听。
ACTIVE：允许普通对话和语音导航；按用户选择输出语音/文字。
QUIET_WAKE：暂停回应，仅在本机侦听唤醒/硬停止控制词。
STOPPED：完全停止聆听，释放本应用持有的媒体轨道、识别器、音频节点与连接。
ERROR：能力不可用，显示恢复路径，不无限重启或继续请求权限。

QUIET_WAKE 的“后台”指应用处于静默待命，不保证浏览器标签切到后台、锁屏、睡眠或关闭页面后继续工作。这些场景分别测试、标明支持情况。
QUIET_WAKE 中：不生成回复、不播报普通聊天、不将普通话语加入会话或记忆，不向远程识别服务/大模型发送环境音或转录。只允许本机唤醒检测所需的短暂处理和有界内存缓冲，及时丢弃，不保存录音。
浏览器原生 SpeechRecognition 可能使用云端识别；即使屏幕没有显示文字，也不能把持续运行它称为“本地静默”。确认设备端能力与中文可用性后才能使用；否则采用明确的本机方案，不偷偷降级为云端常听。
页面须明确显示“暂停回应，仍在侦听唤醒词”和可访问的完全停止入口。不要在静默期间循环朗读状态。

C. 命令优先级与行为

P0 硬停止：如“关闭麦克风”“完全停止聆听”“退出语音”。立即结束本应用采集与输出，清空临时音频，转入 STOPPED。之后网页不能靠已经关闭的麦克风听见唤醒词；恢复需原生启动控件或独立的系统语音控制。
P1 软暂停：“请终止对话”“暂停语音”“暂停回应”。取消在途回复与播报队列，转入 QUIET_WAKE，保存当前业务进度。按用户本轮意图，“请终止对话”是暂停回应；界面说明它仍会侦听唤醒词，避免让人误以为麦克风已关闭。
P2 唤醒：“重新启动语音交流功能”为主词；“重新开启语音功能”为别名。有效唤醒后转入 ACTIVE、恢复语音交流，保留当前会话与页面。它不是重启服务，不新建或清空业务会话。
P3 页面导航与完成指令。
P4 普通业务对话。

控制命令由确定性的本地路由处理，不交给大模型决定系统许可或麦克风开关。避免泛化匹配“停止”导致意外退出；区分“停止朗读”“暂停回应”“完全停止聆听”。
“停止语音播报”/点击“关闭语音播报”：立即取消当前及排队 TTS，转到手动探索；不推断用户视力。若麦克风已获授权且用户同意保持唤醒待命，则进入 QUIET_WAKE，并清楚提示仍侦听唤醒词；始终允许另行关闭麦克风。未获授权时不启动采集。
软暂停与硬停止在模型回复、流式播报、页面切换和等待响应时都可执行，不能只在系统说完后才生效。需要真实的打断监听/回声控制；不得仅靠一个按钮声称语音可打断。
暂停后迟到的模型响应、旧识别回调和旧 TTS 回调不得重新输出或恢复聆听。使用现有取消与请求世代机制，覆盖新状态的竞态。

D. 同一句话中的唤醒与后续指令

用户说“重新启动语音交流功能，进入映照”：只把“进入映照”作为新的导航命令执行一次，不丢失、不重复，不将唤醒前闲聊带入对话。
用户说“重新开启语音功能，今天想要淡一点的妆”：只把后半句作为本次新输入处理一次。
只说唤醒词：恢复后简短回应“我在，请继续”，等待下一句。
软暂停词后附带的普通内容不继续执行。带否定、引用或讨论语境的词句（如“不要重新开启语音功能”）不应仅因包含关键词而激活；设候选校验和误触发测试，并记录实际结果。
必须设计唤醒词边界、检测延迟、短时缓冲与后半句识别。不能假设重新调用现有 SpeechRecognition.start() 能找回启动前已经说出的音频。若采用本地关键词检测，需要另一个可处理唤醒后音频的识别路径；关键词模型本身不会转录后半句。
缓冲有严格时长和内存上限；仅用唤醒后当前话语所需片段，唤醒前内容丢弃。不要上传整段静默历史。TTS回声不能使应用自我暂停或自我唤醒。
长唤醒词的识别率、响应时延和同句边界均需实测；不承诺百分之百准确。

E. 推荐验证路线

先检查现有 Web Speech 生命周期和设备端中文能力，随后优先验证 sherpa-onnx 中文自定义关键词检测与本地识别接入，保持现有 FastAPI 和模型对话 API。
可验证的结构：浏览器在正式授权后采集音频 → 本机 127.0.0.1 语音处理端（或已证实可运行的设备端模块） → 静默只检测控制词 → 唤醒后识别有效指令 → 现有业务 API。
本机服务不等于远程部署服务。将来远程托管时，必须重新说明音频去向，不能继续声称“完全在用户本机”。
核查代码与模型各自许可证、模型文件来源/校验值、Mac/Windows/当前 Python 版本兼容性与启动生命周期。不要让云端大模型负责常听，也不要为了新库破坏现有可运行环境。
无法达到本地静默或同句续接时，将该条标为未完成，并给出原因；不能用视觉动画或预设回复伪装成功。

继承其竞态处理，不把功能做成互不知情的第二套监听器。

映照：继续支持语音引导、打断、重复、跳过与本来已有的检查能力。“这一步完成/下一步”用于妆教步骤；页面级“完成/结束本次装扮”用于结束核心体验。明确区分页面完成和步骤完成，不能让同一识别结果既推进步骤又结束会话。
若原有阶段中“完成”存在冲突，按当前引导上下文明确提示可说的命令，并使用“结束本次装扮”消歧；不能为了路由把未完成步骤、未确认方案或数据库记录直接标为成功。
核心体验结束后给出简短回顾，停留在可操作的完成状态；不强制跳到拾光，不自动保存记忆。用户仍能主动语音/手动打开扩展页面。
所有路由变化同步可见标题、当前导航和键盘/读屏焦点；避免自带TTS与aria-live同时重复长段播报。

体验命名采用用户提出的“全明/黑暗”作为体验偏好名称，可显示“全明 · 手动探索 / 黑暗 · 语音陪伴”，配一句“按偏好选择，随时切换”。不采集或推断视力身份，不因关闭播报就给用户贴标签，也不据此屏蔽页面。此命名不要求新增黑色主题。
“关闭语音播报”进入手动探索；未关闭且已选择语音并获许可时，继续语音陪伴。权限不足时不能将“没有点关闭”当作许可。

七、R5：拾光的可选记忆复用

优先沿用现有记忆同意、偏好记录与日志机制。查明“用户同意保存偏好”和“同意调用既有记忆”当前如何实现；不得擅自将整段聊天或静默音频写入数据库。
本次结束可询问是否记住用户确认的妆容偏好。明确同意才保存；拒绝后不重复劝说，继续可用。
下一次进入倾听/映照，只使用有来源、仍有效且用户授权的记录。例如：“上次你确认喜欢柔和的日常妆，今天想继续尝试吗？”同意后沿用；拒绝后从本次需求重新开始。
无记录、记录已删除、过期或未授权时，不虚构“上次你很喜欢”。为用户提供可访问的查看、修改和删除方式。
保存偏好不等于训练模型；本轮不开展模型训练。

八、实施顺序、验收与交付

只有进入 IMPLEMENT 后执行以下阶段。每阶段先确认输入，再实施最小必要改动，完成有意义的验证；同一授权范围内不额外设置逐步审批。

P0：核对正确目录、现有改动、素材与能力。记录源码/资源回退方式；不要覆盖既有未提交工作，不复制或输出 .env、密钥、录音或私人日志。
P1：统一装饰人物、调整编号和字号、移除首页业务按钮，核查所有页面及静态/减少动态回退。
P2：验证中文本地唤醒与同句续接的技术路径，处理许可、输出开关、软暂停、硬停止和竞态。
P3：接通三步路由、步骤/页面完成消歧以及有同意的记忆复用。
P4：运行现有相关测试、实机语音与视觉验收，记录结果。未来若更新交付包，同步双端说明、资源来源与完整性清单，不打包 .env、虚拟环境、node_modules、私有数据库或录音。

必须可观察的验收场景：
AC01 六个主页面及其回退：没有旧装饰人物残留；苹果、文字保持正确；摄像头真实画面未被替换。
AC02 在桌面和窄屏及200%缩放下，六项编号可见、可操作、顺序正确；键盘焦点和读屏名称明确。截图需包含实际视口尺寸。
AC03 首页不存在旧“开始今天的造型”按钮；具备清楚的手动导航和语音启动入口。
AC04 首次未授权：不会谎称正在听，不会自动批准许可；分别记录允许、拒绝、撤回、不支持和自动播报受阻的实际表现。
AC05 Mac系统语音控制辅助首次操作：按名称/编号进入语音入口，核查真实权限对话框；记录操作系统、浏览器版本及能否无手完成。未测试不能写“支持”。
AC06 已授权：语音“可以开始”进入倾听，“完成”按上下文进入映照，核心体验结束不强制进入拾光。
AC07 回复和TTS进行中说“请终止对话”：旧输出停止，QUIET_WAKE仍可唤醒。静默普通闲聊不触发模型请求、路由、日志/记忆写入或语音回复；用请求计数和本机服务记录证明，不只看屏幕。
AC08 两个唤醒词、单独唤醒、唤醒词紧接导航、唤醒词紧接业务话语：后半句各执行一次，唤醒前普通内容不进入会话。
AC09 否定/引用、背景噪声、TTS回声及连续暂停—唤醒：记录误唤醒与漏唤醒，不使用未实测的准确率。关键控制先做确定性测试，再做真实麦克风试验。
AC10 “关闭麦克风”：本应用所有音轨/识别与音频连接释放，不能自动重开；已关闭的麦克风不假装仍可听到网页唤醒词。其他应用占用设备不由本应用控制。
AC11 “关闭语音播报”：队列清空，手动操作有效，用户能分清当前是否仍侦听唤醒词；明确唤醒可恢复语音交流。
AC12 导航、暂停、结束期间旧模型/识别/TTS回调不会继续说话或重开麦克风；同一句指令不重复发送。
AC13 记忆同意、拒绝、无记录、删除记录、下次复用：只用真实授权记录，不自动保存或重放静默内容。
AC14 标签切后台、锁屏、断网、设备拔出、权限撤回：说明实际行为与恢复方式，不保证网页具有系统级常驻能力。
AC15 Mac和Windows启动仍可用；未经Windows实机验证就标为未测试，不能把Mac结果当双端验收。

验证计划（不是本轮已运行的结果）：
前端：在 frontend 中执行 npm test 与 npm run build；对关键语音状态/竞态、指令分流和记忆同意增加必要测试，UI小改动以实际浏览器检查为主。
后端如有改动：使用项目自身Python执行既有pytest，保留pytest.ini的pythonpath与工作区basetemp设置；新增语音端只测试必要协议与生命周期，不编造命令。
本轮不安装库、运行新模型、触发麦克风/摄像头许可或改动测试；这些属于后续实施。

实施交付须包含：实际修改文件与作用、真实截图/操作记录、运行过的检查及结果、支持环境、未测项、缺失素材和回退方式。将“代码存在”“构建通过”“实机语音通过”“视觉验收通过”分开记录。
遇到缺素材或能力不支持时，说清楚具体阻塞条目，完成不受影响的已授权部分；不得把部分完成汇报为整轮完成。
